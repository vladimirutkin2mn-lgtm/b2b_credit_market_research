# BB-02 — сегменты клиентов и правила измерения

Дата подготовки: **2026-10-07, Europe/Moscow**. Проверка внешних страниц: 2026-10-06 UTC. Входная версия репозитория: `0170f22814b5f0deb3f2a40100a1a1200e9cd5e6`.

Статус: методология BB-02 подготовлена; определения предлагаются для исследования, а не выдаются за утверждённые показатели Ozon Банка или раскрытые показатели компаний. Словарь: [metric_definitions.csv](../../data/b2b_banking/metric_definitions.csv). Фактические значения собираются отдельно в `metrics.csv`; в BB-02 они не добавляются.

## 1. Вывод для исследования

Сравнивать нужно не число открытых счетов, а **стоимость получения внешней компании, которая выполняет полезные задачи, даёт достаточно качественных данных и приносит прибыль после кредитных потерь**. При этом путь через кредит может начинаться до открытия собственного счёта.

Для дальнейшего сбора фиксируются три независимых уровня:

- **Клиент:** правовая форма, размер и зрелость бизнеса, отрасль, потребность, связь с Ozon, группа связанных компаний.
- **Путь:** причина первого прихода, канал, подключённые продукты и последовательность событий.
- **Результат:** полезная активность, удержание, доступные данные, кредитная пригодность, выдача, качество кредита и экономика когорты.

Это аналитическая рамка, не установленный факт о преимуществе конкретной модели. Данных для ранжирования сегментов по прибыли Ozon Банка нет: BB-G01/05 в [реестре пробелов](remaining_evidence_gaps.md).

## 2. Единица клиента и границы внешнего бизнеса

Основная единица — `business_id`: один клиентский субъект в заданной юрисдикции. В российских агрегатах предлагается стабильный идентификатор юрлица или ИП; в иностранных данных — идентификатор и граница, доступные у провайдера. Филиал, пользователь кабинета, карта, счёт и дополнительная валюта не создают нового клиента автоматически.

Группа связанных субъектов — отдельный `group_id`. Показывать число клиентских субъектов и число групп раздельно; не заменять одну метрику другой. Правила объединения и изменения состава группы документировать. Для риска/концентрации и для привлечения границы могут отличаться. Ни клиентские идентификаторы, ни внутренние связи не публикуются в открытом репозитории.

Для цели исследования предлагается фиксировать:

| Поле | Правило |
|---|---|
| `ozon_seller_status_at_entry` | seller / non_seller / unknown на дату первого отношения; основание и дата проверки |
| `related_group_has_ozon_seller` | yes / no / unknown; отдельный признак, не молчаливое исключение группы |
| `other_platform_seller` | yes / no / unknown; внешняя платформа не равна Ozon |
| `bank_relationship_at_entry` | новый для банка / существующий РКО / существующий кредитный / иной / неизвестно |
| `relationship_changed_at` | Последующие изменения статуса хранятся отдельно от исходной когорты |

Рабочее правило целевого внешнего бизнеса — `non_seller` на дату входа. Это **proposed**, а не утверждённая политика банка. Неизвестный статус нельзя считать подтверждённым внешним клиентом. Не продавец Ozon не означает «никак не связан с экосистемой»; границу связанных групп и допустимость таких клиентов уточнить внутри банка. Клиент, ставший продавцом позже, сохраняет первоначальную когорту; текущий состав базы показывается отдельным срезом.

## 3. Сегментация: несколько осей вместо одной категории SME

### 3.1. Правовая форма и налоговый статус

| Аналитический разрез | Как хранить | Ограничение |
|---|---|---|
| Юридическое лицо | Точное местное наименование формы, страна, нормализованная категория `legal_entity` только после проверки | Не объединять все иностранные LLC, partnerships и «business customers» с российскими ООО без основания |
| Индивидуальный предприниматель / сопоставимая местная форма | Местная форма и отдельная категория `individual_business` | «Sole trader» не автоматически равен всем самозанятым |
| Физлицо с самостоятельной профессиональной деятельностью | Местный статус и категория `individual_professional` | Не включать в юрлица; смешанный B2C/B2B-охват раскрывать |
| Налоговый режим / статус самозанятого | Отдельное поле, возможен статус у уже учтённого субъекта | Не создавать второй бизнес поверх ИП только из-за налогового статуса |
| Форма не раскрыта | `unknown` либо `mixed_not_disaggregated` | Не восстанавливать долю юрлиц из названия «SME» |

Первичная проверка: ФНС описывает НПД как специальный налоговый режим и указывает физических лиц и ИП среди применяющих его при соблюдении условий — **BB-C0014 / BB-S0011**, Россия, страница на дату доступа, fact, Medium. Поэтому для российской аналитики предлагается хранить статус ИП и НПД раздельно. Это правило учёта, не консультация о допустимости режима конкретному клиенту. [Источник ФНС](https://npd.nalog.ru/), разделы «Что такое…» и «Кому подходит…».

Доля юрлиц `legal_entity_share` всегда требует явно обозначенной базы: подключённые, активные или заёмщики. Если часть форм неизвестна, показывать долю неизвестных; доля среди классифицированных не равна доле всей базы.

### 3.2. Размер, возраст и наблюдаемость

**Размер.** Хранить исходное определение провайдера или статистики и его назначение: продукт, кредитная политика, государственная программа, статистическое обследование. Если публикуются численность, оборот или активы, сохранять показатели с периодами, но не придумывать единые мировые пороги.

Еврокомиссия описывает определение SME через численность и оборот либо итог баланса; для компании в группе может требоваться учёт данных группы — **BB-C0015 / BB-S0012**, ЕС, страница на дату доступа, fact, Medium. [Официальное определение](https://single-market-economy.ec.europa.eu/smes/sme-fundamentals/sme-definition_en). Страновые пороги из прежнего `data/country_sme_definitions.csv` — указатель для проверки, а не автоматически обновлённая база. Числовые пороги стран в этом задании не импортированы.

**Зрелость.** Предлагаемые группы: до устойчивых продаж; продажи начались, история короткая; устойчиво работающий бизнес; расширение/смена модели; неизвестно. Хранить дату регистрации, дату начала операций и доступную длину истории **отдельно**. Молодая компания может иметь историю основателя или группы, но это не история самого заёмщика.

Числовой порог «молодой / зрелый» не установлен. Для каждого продукта он берётся из его условий; для внутренних сравнений согласуется до расчёта и маркируется как предложенный. Старая дата регистрации не доказывает стабильный денежный поток или низкий риск.

Отдельные признаки: наличие сотрудников; число площадок/юридических субъектов; сезонность; структура клиентов и поставщиков; история в своём банке, другом банке, платёжной платформе или отраслевом ПО; полнота и свежесть данных. Отрасль и сезонность не заменяют собственную кредитную оценку.

### 3.3. Отрасли и финансовые задачи

Матрица ниже — план исследования потребностей, **не эмпирический рейтинг привлекательности**.

| Сегмент | Возможная частая задача | Кредитная потребность для проверки | Что может нарушить механизм |
|---|---|---|---|
| Профессиональные услуги и небольшие B2B-сервисы | Выставить счёт, сверить оплату, работать с бухгалтером | Дождаться платежа клиента, оплатить зарплату/расходы | Нерегулярные операции, концентрация заказчиков |
| Розничная торговля и внешние онлайн-продавцы | Принимать оплату, сверять продажи, платить поставщику | Закупка и сезонный запас | Возвраты, непрозрачные продажи вне сервиса |
| Рестораны и небольшие сервисные точки | Касса, платежи, выплаты и расходы | Запасы, ремонт, оборудование | Низкая маржа, зависимость от площадки/партнёра |
| Оптовики и поставщики | Счета, дебиторка, закупки, согласование платежей | Запас и отсрочка покупателю | Споры по поставке, концентрации, длинный цикл |
| Небольшое производство | Платежи за сырьё, заказы, фонд оплаты труда | Производственный цикл, оборудование | Длинный цикл, слабая наблюдаемость запасов |
| Транспорт и логистика | Расходы, выплаты, документы по выполненным работам | Эксплуатация, техника, ожидание оплаты | Лизинговая/долговая нагрузка, неполная маржа |
| Строительство и подрядчики | Проекты, акты, расходы и платежи исполнителям | Исполнение контракта и задержка оплаты | Неравномерность, спорная дебиторка |
| Бизнес с международными расчётами | Валютные платежи, документы, сверка | Оплата поставки и оборотный цикл | Доступность маршрута, комплаенс, внешние ограничения |
| Стартапы с привлечённым капиталом | Расходы, согласования, остатки | Потребность и источник погашения исследуются отдельно | Инвестиционный остаток не доказывает операционные продажи |

По кейсам собирать источник оплаты, частоту задачи, точку возникновения кассового разрыва, наблюдаемость данных, тариф и кредитную пригодность. Заявленная потребность не равна доказанному спросу и не гарантирует кредит. Свежесть и российская доступность международных решений проверяются в BB-09/10.

## 4. Четыре пути: сценарии пересекаются, но не должны удваивать клиентов

| Путь | Первое обещание клиенту | Событие подключения | Первая полезная задача | Что проверять до кредита |
|---|---|---|---|---|
| Сначала счёт | РКО, переход и удобство расчётов | Завершённое подключение счёта | Реальный платёж/поступление либо согласованная финансовая задача | Перенос операций, активность, данные, стоимость привлечения |
| Сначала финансовая задача | Получить оплату, оплатить счёт, управлять расходами/бухгалтерией | Рабочий доступ к нужной функции | Завершённая задача, не просто вход или демозапуск | Регулярность, принятие функции, право/возможность использовать данные |
| Сначала партнёр | Финансовый сервис в доверенном канале или рабочем ПО | Доступ к сервису через конкретного партнёра | Подтверждённая задача в партнёрском сценарии | Дедупликация клиентов, права на данные, комиссия, владелец отношения/риска |
| Сначала кредит | Финансирование конкретной потребности | Рабочий доступ к кредитному процессу, не обязательно счёт | Завершённая подача данных/заявки; выдача учитывается отдельно | Внешние данные, отбор, стоимость оформления, удержание после кредита |

Партнёр — канал; остальные пути преимущественно описывают причину входа. Поэтому хранить:

- `entry_need`: account / workflow / credit / mixed / unknown.
- `entry_channel`: direct / partner / accountant / referral / other / unknown.
- `primary_path_at_entry`: один основной путь только при известном основании; mixed/unknown допустимы.
- `path_tags`: дополнительные пересекающиеся сценарии.
- `product_bundle`: счёт, платежи, ПО, собственный кредит, партнёрский кредит — отдельные признаки.

Если первичное отношение возникло через партнёра, это может быть основной партнёрский сценарий с дополнительным мотивом account/workflow/credit. Правило атрибуции фиксировать до сравнения; не переносить клиента в «успешный» путь после выдачи. В разрезе основной категории один клиент считается один раз. Сумма пересекающихся `path_tags` не является общей базой. Путь не следует назначать всем клиентам компании по одному рекламному экрану.

Для собственного РКО измеряется последующая кредитная конверсия; для кредита как входа — также последующее подключение и активность РКО/ПО. Отсутствие счёта на входе не считается неуспехом кредитного пути.

## 5. События и определения активности

### 5.1. Не одна универсальная воронка

Фиксировать самостоятельные события: регистрация → подключение продукта → первая полезная задача; доступ к данным → предварительная пригодность → предложение → заявка → решение → фактическое использование кредита.

Это перечень возможных событий, **не обязательный порядок для всех путей**. Заявка может быть раньше предложения; данные могут существовать до подключения; кредит — до активного собственного счёта. Предложение, лимит и одобрение не являются выдачей.

Начальная точка когорты `t0` задаётся до сравнения. Для базы отношений — первое завершённое подключение выбранного сервиса. Для эффективности привлечения до подключения нужна отдельная когорта контактов/заявок, чтобы не потерять расходы на непрошедших проверку. Если для кредитного пути доступна лишь дата заявки, так и называть когорту, не сравнивать её время с когортой открытых счетов как одинаковый показатель.

Минимальная внутренняя запись события: стабильные business_id и при необходимости group_id; event_id; timestamp и timezone; продукт; тип и результат события; источник данных; канал; кредитная заявка/договор при наличии; валюта/сумма при наличии; признаки тестового, технического, отменённого события и связанного контрагента. В репозитории хранятся только методика и публичные агрегаты.

### 5.2. Два вида полезной активности

**Платёжная:** завершённая реальная операция для бизнеса — например, оплата поставщику, налог/зарплата, поступление от клиента. **Рабочая:** завершённая финансовая задача без движения денег — например, отправленный реальному клиенту счёт или завершённая сверка. Счёт ещё не является оплатой; подготовленный черновик не является завершённой задачей.

Разделить `active_business` (квалифицирующая денежная активность) и `workflow_active_business` (квалифицирующая задача). Первое полезное событие `first_useful_operation` имеет пометку money/workflow/credit_process; при сравнении объединять только одинаковые определения. Само получение кредита не подменяет регулярную операционную активность счёта.

**Нет единого порога активности.** До расчёта согласовать типы полезных событий, окно W, минимальную частоту K, правила суммы/отмены и версию классификатора. Числа W/K в BB-02 не назначены. Без них показатель не рассчитывается. Официальное определение компании записывать дословно по смыслу с источником; если оно включает только входы/карточные события, не переименовывать в сопоставимую платёжную активность.

### 5.3. Что исключать и что показывать отдельно

| Событие | Предлагаемое правило | Почему |
|---|---|---|
| Перевод между счетами одного клиента | Не считать самостоятельной полезной внешней операцией; учитывать миграцию/остатки отдельно | Перемещение денег не доказывает использование для операционной задачи |
| Перевод связанной компании | Маркировать отдельно; не исключать автоматически реальную поставку/зарплату | Связанность может означать как технический оборот, так и реальную деятельность |
| Банковский бонус, cashback, тестовая операция | Не использовать сами по себе для активации | Иначе покупка регистрации выглядит как спрос |
| Выдача кредита и его погашение | Отдельный кредитный поток; не выдавать за клиентскую выручку и активность РКО | Иначе кредит механически «доказывает» активацию |
| Отменённая операция/возврат | Событие и сторно связать; исходное и нетто показывать по правилам показателя | Не считать ошибку и исправление двумя полезными задачами |
| Рефинансирование | Валовую выдачу и новые деньги разделить при доступности | Замена старого долга не равна новому денежному потоку |
| Вход в кабинет, добавление сотрудника, подключение интеграции | Считать настройкой, если не доказана завершённая задача | Наличие доступа не равно регулярному использованию |

Операции между разными бизнесами не становятся полезными только потому, что контрагенты формально различны. Для технических/круговых операций нужны классификация и контроль. Если публичное раскрытие не даёт очистки, сохранить его охват и ограничение, а не вычитать предполагаемую величину.

## 6. Метрики: знаменатели и часы наблюдения

| Блок | Основные ID | Главное правило |
|---|---|---|
| База | unique_business, registered_business, connected_business, opened_account, legal_entity_share | Субъект, продуктовый доступ, счёт и пользователь раздельно |
| Активность | active_business, workflow_active_business, first_useful_operation, activation_rate, time_to_first_useful_operation | Одно определение полезной задачи и полное окно от t0 |
| Удержание | retention, reactivated_business, paying_business, primary_financial_service | Неизменная исходная когорта; платёж тарифов и активность раздельно |
| Данные | data_history_duration, data_coverage, data_consent_valid, data_ready | История ≠ доступ ≠ полнота ≠ достаточность для политики |
| Кредит | credit_need_observed, credit_eligible, credit_offered, credit_applicants, credit_approved, credit_take_up, borrowers | Спрос, предварительная пригодность, решение и выдача раздельно |
| Повтор | active_borrowers, repeat_borrowers, originations, loan_stock, average_loan_stock | Повторный договор не создаёт нового уникального клиента |
| Экономика | acquisition_cost_total, cac_opened, cac_active, cac_borrower, cohort_profit_before_capital, cohort_profit, payback | Сопоставимая когорта, затраты и созревание риска |

Полные формулы, числитель, знаменатель, исключения и незаданные параметры находятся в CSV. Первые семь колонок исходного формата сохранены; добавлены поля для границ расчёта, версии и происхождения определения. Все определения сейчас имеют предложенный аналитический статус. Не помещать эти определения в `claims.csv` как раскрытые факты компаний.

Правила:

1. Процент — отношение согласованных числителя и знаменателя, умноженное на 100. Нулевой знаменатель даёт «не применимо», неизвестный — «данных нет», а не ноль.
2. Подключённые → заёмщики и активные → заёмщики — разные показатели. Во втором числитель ограничивается той же активированной группой; поздняя активация после кредита не доказывает причинного пути «активность → кредит».
3. Одобрения по заявкам и по уникальным компаниям раздельны. Для нового исследования основной approval rate определён на уровне компаний одной когорты завершённых рассмотрений; прежний `FUNNEL_APPROVAL_RATE` по заявкам остаётся другим показателем. Отказ не равен 1 − одобрение при наличии ожидания/отзыва/условного решения.
4. Для удержания фиксировать набор впервые активированных в исходном окне; не исключать закрывшихся, иначе оценка завышается. Активность в последующем окне и непрерывная активность между окнами — разные определения. Возврат после паузы маркировать отдельно.
5. Время до первой задачи показывать по активировавшимся вместе с долей неактивировавшихся и длительностью наблюдения. Медиана среди дошедших не описывает всю когорту. Коротко наблюдаемую компанию нельзя считать неактивной за ещё не завершившееся окно.
6. Долю основного финансового сервиса нельзя вычислить только из операций одного банка. Нужен наблюдаемый общий сопоставимый поток; заявление клиента хранить как самооценку, не как измеренную долю.
7. Портфель на дату, средний портфель и сумма выдач различаются. Для среднего предпочтительно взвешивание по времени; приближение по началу/концу маркировать отдельно.
8. Денежные показатели по валютам/периодам сначала хранить исходно. Конвертация валют — отдельный расчёт с источником курса и датой, не часть предлагаемого определения.
9. Нельзя перемножать конверсии разных компаний или показателей с разными когортами. Произведение допустимо только для одной доказанной вложенной последовательности; для пересекающихся путей считать по субъектам и событиям.

## 7. Когорты, атрибуция расходов и созревание

Предлагаемый ключ когорты: месяц t0 × страна × форма клиента × канал × основной путь × статус внешнего бизнеса. Размер/возраст/отрасль — дополнительные разрезы, если доступны. Источник и версия всех правил обязательны; при недостаточной выборке объединение согласуется явно, не маскирует различия.

Сравнивать на одинаковом горизонте H после t0 и одинаковой дате доступных данных. Отдельно фиксировать возраст кредита после выдачи: одинаковый возраст отношений не означает одинаковое созревание потерь. Выжившие активные клиенты не заменяют исходную когорту для оценки её прибыли.

Первичный канал — по заранее согласованному правилу; последующие касания хранить отдельно. Нельзя одновременно полностью списать одни расходы на несколько каналов. Стоимость активированного клиента включает согласованную долю расходов на неактивировавшихся; стоимость заёмщика — долю расходов и на незаёмщиков. Дополнительные затраты активации/проверки/оформления учитывать отдельно и объединять один раз в прибыли.

Оплата партнёру, подписка или выручка группы не являются CAC автоматически. Для CAC указать период расходов, когорту, включение персонала/проверок/бонусов и метод распределения. Если расходы календарного месяца нельзя привязать к клиентской когорте, публиковать периодный показатель с оговоркой, не создавать точный когортный результат.

## 8. Прибыль: два уровня вместо смешения P&L и капитала

Предлагаемая форма расчёта без числового прогноза:

`Результат когорты до платы за капитал = чистые доходы РКО/платежей/ПО + кредитный результат после FTP − привлечение − активация/проверки − обслуживание/взыскание − кредитные потери по выбранной методике − прочие распределённые затраты`.

`Экономическая прибыль когорты = результат до платы за капитал − плата за выделенный капитал`.

- `cohort_profit_before_capital` — первый уровень. Он не считается официальной бухгалтерской прибылью, пока не определены налог, резервы, признание комиссий и распределение затрат.
- Существующий `cohort_profit` уточнён как **экономическая прибыль после платы за капитал**. Плата за капитал не выдаётся за бухгалтерский расход.
- В кредитном результате FTP уже учтён. Доход/выгоду остатков учитывать отдельно только если они не включены в FTP или другой строке. Выбранный способ закрепить; одну и ту же выгоду нельзя считать дважды.
- В доходах партнёрского продукта учитывать доход, принадлежащий банку, а не все проценты кредитора-партнёра; долю риска, гарантии и регресс исследовать отдельно.
- Для потерь выбрать одну согласованную основу: бухгалтерский расход на обесценение либо экономические ожидаемые/реализованные потери для заданного горизонта. Не вычитать одновременно списания и резервирование той же потери. Молодую когорту не объявлять прибыльной «после риска» только из-за малых текущих списаний.
- Суммы выдач и погашений тела не являются процентным доходом или расходом прибыли. Налог, денежные потоки и дисконтирование должны быть названы явно.
- `payback` требует полностью согласованной накопленной экономики. Если горизонт ещё не завершён или после первого пересечения нуля прибыль снова отрицательна, показывать это; обещать устойчивую окупаемость нельзя.

Для управленческого выбора отдельно нужны: прирост кредитной прибыли и совместная экономика всех сервисов. Прибыль РКО не доказывает дополнительность кредита; приписывание эффекта одной функции требует сравнения или эксперимента, а не только суммы доходов её клиентов.

## 9. Как записывать раскрытые метрики компаний

Для наблюдения обязательны: metric_id, company, страна, продукт, сегмент, форма клиента, значение/единица/валюта, период/дата, определение источника, знаменатель и охват, source_ids/claim_ids, статус, уверенность и ограничения.

Если компания считает активных по своему правилу, сохранять это правило в `metrics.definition` и пометку в limitations. Предложенное определение не заменяет её опубликованное определение. Если нет исходных данных для пересчёта, сравнение качественное или внутри группы одинаковых определений.

Функция, использование и результат записываются раздельно. История транзакций не доказывает кредитную пригодность; достаточность данных не доказывает спрос. Неизвестный числитель/знаменатель не заполняется расчётным «правдоподобным» значением.

Два проверенных регуляторных тезиса BB-C0014/15 описывают границы сегментов, а не значения бизнес-метрик. Стартовые продуктовые тезисы BB-C0001–0013 не получили выдуманных значений активности или эффекта.

## 10. Проверка определений на ошибочных сценариях

Приёмочные сценарии — логические тесты, не рыночные числа:

| Сценарий | Ожидаемый учёт |
|---|---|
| Компания открыла дополнительные счета и добавила сотрудников | Счета/пользователи выросли; unique_business не вырос |
| ИП перешёл на НПД | Обновился налоговый статус; не появился второй клиент |
| Клиент получил бонус и переместил деньги между своими счетами | Нет подтверждённой полезной внешней активации |
| Клиент отправил реальный счёт, но денег ещё нет | Возможна workflow-активность; нет соответствующего денежного поступления |
| Клиент передал полную историю, но не прошёл кредитную политику | Может быть data_ready; не credit_eligible |
| Лимит доступен, но не использован | Предложение/одобрение возможно; нет фактической выдачи |
| Компания получила несколько кредитов | Уникальный заёмщик один; repeat и выдачи учитываются отдельно |
| Заёмщик пришёл без своего РКО | Кредитный путь учитывается; счёт и его активация могут отсутствовать |
| Партнёр привёл клиента для оплаты поставщику | Канал partner плюс мотив workflow; не два уникальных клиента |
| Когорта ещё не наблюдалась полное окно | Показатель этого окна недоступен, а не ноль |
| Закрывшиеся клиенты исключены из исходной когорты удержания | Тест должен выявить изменение знаменателя |
| Расход/выгода уже включены в другую строку прибыли | Не учитываются повторно |
