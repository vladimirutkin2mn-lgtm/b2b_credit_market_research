# Возможности Ozon Банка и проекты пилотов

## Два сценария входа и канал для их проверки

Условный первый приоритет — кредит по внешней истории (BB-O01) и финансирование оплаты поставщика (BB-O02). Бухгалтерский канал BB-O03 может использоваться для обоих сценариев. Это два продуктовых эксперимента с выбором канала, а не три независимых проекта. Ожидаемые эффекты остаются гипотезами с низкой уверенностью: внутренние показатели, утверждённые мощности и риск-аппетит не предоставлены.

| Направление | Что проверяется | Условие первого приоритета |
| --- | --- | --- |
| BB-O01: кредит по внешней истории | Можно ли привлечь и оценить компанию до накопления своего оборота | Проверяемый источник истории, достаточное покрытие, работающий кредитный процесс |
| BB-O02: финансирование оплаты | Улучшает ли предложение в момент реальной закупки результат исходной когорты | Подтверждение сделки и исполнения, контроль повторного финансирования |
| BB-O03: бухгалтерский канал | Меняет ли канал стоимость активной компании в O01 или O02 | Доступ к целевым клиентам, конкретная полезная задача, учёт всех канальных затрат |
| BB-O04–O07 | Партнёр, зарплата, перенос оборота, подготовка платежа | Следующая очередь при наличии соответствующей инфраструктуры; O07 может поддержать O02/O05 |

Порядок меняется, если исходные условия не выполнены. Наличие собственного канала, интеграции или качественной истории может сделать другой сценарий дешевле. Без этих внутренних данных нельзя объявить A экономически лучшим вариантом. Карточки ниже — проекты протоколов для обсуждения, а не утверждённые планы запуска.

## Общий протокол: что фиксируется до первой заявки

| Параметр | Правило для всех пилотов |
| --- | --- |
| Когорта N | Все исходно назначенные компании, включая отказы, неактивных клиентов, просрочку и дефолты. Приглашённые и самостоятельно обратившиеся компании учитываются раздельно; одна компания имеет один идентификатор |
| Контроль | При случайном распределении анализировать по исходному назначению. Если оно невозможно, заранее задать сопоставление по сегменту, потребности и риску; результат такого сравнения не называть доказанным причинным эффектом |
| Размер и срок | До запуска определить N, горизонт H, базовый уровень, минимальный обнаружимый эффект и допустимые ошибки. H должен покрывать повторение задачи, а для кредитного вывода — достаточную зрелость потерь |
| Один главный KPI | Заранее выбрать один показатель решения для каждой фазы. Данные процесса, конверсия, сроки и ошибки остаются диагностическими метриками и ограничителями |
| Экономика | Считать вклад всей исходной когорты по правилам главы 4: канал, поддержка, фондирование, потери, капитал. Отдельно показать результат проекта после разработки и общих затрат; не удваивать расходы |
| Бюджет и остановка | До запуска утвердить бюджет, лимиты выдач и концентрации, границы качества/потерь/затрат и порядок остановки. Численные пороги здесь не выдуманы: их задают финансы, риск и владелец продукта по внутренним данным |
| Ответственность | Назначить владельца решения и владельцев данных, риска, финансов и операций. Названия ролей в карточках — предложения; назначенных людей в исследовании нет |

При недостаточной зрелости кредитного риска можно сделать вывод о процессе, но нельзя объявить доказанную прибыль. Для решения «продолжить / изменить / остановить» сравниваются результат с контролем, ограничения и полная экономика на одном горизонте. Продление наблюдения заранее отличается от продолжения выдач.

## BB-O01. Кредит новому клиенту по внешней истории

Задача — получить оборотное финансирование до накопления истории нового счёта. Сбор документов подтверждает готовность к оценке; кредитная активация наступает при выдаче или фактическом использовании лимита.

| Поле протокола | Проект проверки |
| --- | --- |
| Клиент и N | Зрелые внешние компании в услугах, опте или небольшом производстве. ИП и юрлица, входящие заявки и приглашения — отдельные группы; в N остаются все исходные участники |
| Сравнение | Одинаковые сегмент и риск-политика: текущий процесс против оценки по внешней истории. Сначала оценка без выдачи; после проверки данных — ограниченная кредитная фаза |
| Главный KPI | Фаза данных: полная стоимость пригодного к оценке заёмщика по заранее заданным критериям. Кредитная фаза: прирост вклада на исходную компанию против контроля после созревания риска |
| Данные и допуск | Проверить происхождение, охват счетов, свежесть, долги и права доступа. До выдачи нужны рабочие договор, взыскание, фондирование и независимый риск-допуск |
| Экономика | Включить ручную проверку, отказы, сбор данных, привлечение и все кредитные потери. Повторные платежи в новом банке не являются обязательной ступенью до первой выдачи |
| Остановка | При непроверяемых данных остановить кредитную фазу; при превышении утверждённых рисковых или экономических границ прекратить новые выдачи. Сохранять наблюдение всей когорты |
| Предлагаемый владелец | Руководитель кредитного продукта; совместно — риск, данные, операции и финансы. До старта они фиксируют N, H, бюджет и пороги |

Опора: BB-C0241, BB-C0251, BB-C0270, BB-C0401. Ограничения: BB-C0400, BB-C0411. Эффект для Ozon Банка не установлен.

## BB-O02. Оплата поставщика с финансированием подтверждённого счёта

Задача — выполнить закупку при временном недостатке денег. Активное действие — исполненная оплата реальному поставщику, связанная с выданным финансированием; подготовленный документ ещё не является оплатой.

| Поле протокола | Проект проверки |
| --- | --- |
| Клиент и N | Допущенные внешние компании с подтверждённой закупкой. В исходную когорту включить все назначенные компании, а не только выданные и погашенные сделки |
| Сравнение | Случайно предложить обычный кредит либо кредит внутри оплаты при одинаковой риск-политике. Разделить эффект интерфейса и эффект иных цены или условий |
| Главный KPI | Фаза процесса: доля исходных компаний с исполненной финансируемой оплатой. Зрелая фаза: прирост вклада на исходную компанию против контроля после всех потерь и затрат |
| Данные и допуск | Документ, получатель, реальность сделки, аффилированность, повторное финансирование и банковское исполнение. Возвраты и отмены учитывать отдельно |
| Экономика | Считать прирост кредита против обычного предложения, проверку сделки, поддержку, стоимость ошибок, возвратов и дефолтов; учитывать все исходные компании |
| Остановка | Превышение заранее заданных границ фиктивных сделок, повторного финансирования, ошибок или убытка. Быстрая оплата сама по себе не оправдывает ухудшение риска |
| Предлагаемый владелец | Руководитель кредитного продукта вместе с владельцем платежей; риск, противодействие мошенничеству, операции и финансы |

Опора: BB-C0054, BB-C0056, BB-C0405. Ограничения: BB-C0390, BB-C0409. Эффект для Ozon Банка не установлен.

## BB-O03. Бухгалтерский канал для O01 или O02

Бухгалтер — канал привлечения и помощи клиенту. В каждом тесте заранее выбрать один сценарий: внешний кредитный запрос либо оплата поставщику. Не смешивать их результаты в единую конверсию.

| Поле протокола | Проект проверки |
| --- | --- |
| Клиент и N | Внешние компании с обслуживающим бухгалтером и выбранной потребностью. Зафиксировать уникальные компании и принадлежность к бухгалтеру; повторные контакты не увеличивают N |
| Сравнение | При возможности распределять бухгалтеров между предложением и контролем, чтобы избежать перетекания клиентов. Учитывать группировку при расчёте N и эффекта; иначе использовать сопоставимые группы с оговоркой о причинности |
| Главный KPI | Фаза канала: стоимость повторно активной компании в O02 либо пригодного к оценке заёмщика в O01. Кредитная фаза: прирост вклада на исходную компанию |
| Данные и допуск | Проверить ценность сверх существующих интеграций с 1С, согласие клиента, разделение полномочий и атрибуцию. Бухгалтер не заменяет полномочие бизнеса |
| Экономика | Включить вознаграждение, интеграцию, поддержку и ручную работу; отнести канальные затраты к выбранному сценарию один раз. Пригодность заёмщика задать до теста |
| Остановка | Нет повторения выбранной задачи/пригодных заявок либо стоимость превышает установленную границу. Открытие запасных счетов не считается успехом |
| Предлагаемый владелец | Руководитель партнёрского канала с владельцем O01 или O02; операции, риск, финансы и аналитика |

Опора: BB-C0053, BB-C0160, BB-C0417. Ограничение: BB-C0173. Это канал для сценария, а не самостоятельное доказательство кредитного спроса.

## BB-O04. Отраслевой партнёр и контекстное финансирование

Проверяется один партнёр и один сегмент, например офлайн-торговля или рестораны. Наличие операций у партнёра не гарантирует полной финансовой картины бизнеса.

| Поле протокола | Проект проверки |
| --- | --- |
| Клиент и N | Все исходно назначенные компании выбранного партнёра и сегмента. Не ограничивать N только клиентами, принявшими кредитное предложение |
| Сравнение | Контрольная группа приглашений при одинаковом доступе к базовому сервису. Сначала проверить полезность и покрытие данных, затем кредитную фазу |
| Главный KPI | Фаза данных: доля исходных компаний с пригодной полной историей. Зрелая фаза: прирост вклада на исходную компанию после доли партнёра и риска |
| Данные и допуск | Потоки партнёра дополнить внешней историей. В договоре задать владельцев данных, кредитора, распределение потерь, вознаграждение и действия при выходе партнёра |
| Экономика | Учесть комиссию, интеграцию, поддержку и взыскание. Уже созданная дистрибуция зарубежного игрока не является бесплатной предпосылкой для банка |
| Остановка | Недостаточное покрытие, превышение границы концентрации или зависимость процесса от недоступного партнёра. Предусмотреть резервный сбор данных и возврат долга |
| Предлагаемый владелец | Руководитель отраслевого партнёрства вместе с кредитным продуктом; данные, риск, юристы, операции и финансы |

Опора: BB-C0176, BB-C0209, BB-C0283. Ограничения: BB-C0231, BB-C0234, BB-C0314. Эффект для Ozon Банка не установлен.

## BB-O05. Зарплатная или платёжная задача как первый шаг

Полезное действие — своевременно исполненная ведомость или пакет платежей. Исходящие выплаты описывают только часть деятельности и сами по себе не подтверждают выручку или долговую нагрузку.

| Поле протокола | Проект проверки |
| --- | --- |
| Клиент и N | Внешние компании услуг с регулярными выплатами; все исходно назначенные компании, включая не завершивших подключение |
| Сравнение | Новая задача против текущего процесса на случайно распределённых либо заранее сопоставленных группах. Кредитную фазу подключать отдельным решением |
| Главный KPI | Сервисная фаза: доля исходных компаний, повторивших корректно исполненную задачу. Экономический вывод: вклад задачи на исходную компанию; кредитный вывод — отдельно после зрелости риска |
| Данные и допуск | Подтверждение исполнения, получатели, роли и связь с учётом. Для кредита дополнительно нужны входящие потоки и сведения о долгах |
| Экономика | Доход задачи минус полная стоимость подключения, исполнения, исправлений и поддержки. Проверить самостоятельную полезность сервиса |
| Остановка | Ошибки, задержки или стоимость выше согласованной границы. Нехватка кредитных данных останавливает кредитную фазу, но не автоматически полезный сервис |
| Предлагаемый владелец | Руководитель платёжного/зарплатного продукта; операции, аналитика и финансы, а для кредита — кредитный продукт и риск |

Опора: BB-C0337, BB-C0391, BB-C0417. Граница: BB-C0384 относится к самостоятельной ценности платежей, а не к измеренной конверсии в кредит.

## BB-O06. Овердрафт с подтверждённым переносом оборота

Задача — резерв ликвидности для зрелого бизнеса. Переносом считается изменение реальных внешних поступлений и платежей, а не движение выданных банком кредитных средств.

| Поле протокола | Проект проверки |
| --- | --- |
| Клиент и N | Сопоставимые зрелые внешние компании, допущенные по одинаковой риск-политике. Учитывать все исходные назначения и цену отказа от миграции |
| Сравнение | Обязательный против постепенного переноса конкретного вида оборота. До старта задать знаменатель и способ проверки внешних потоков |
| Главный KPI | После достаточного горизонта: прирост вклада на исходную компанию против контроля. Реальный перенос и использование лимита — диагностические показатели |
| Данные и допуск | Свои и внешние операции, остатки, долги, стоимость помощи с переходом. Пересмотр лимита и риск-решение должны быть независимыми |
| Экономика | Совместный вклад РКО и кредита с фондированием и капиталом. Скидки и бонусы за счёт банка — расходы; внешнюю субсидию показать отдельно и проверить результат без неё |
| Остановка | Слабый перенос или результат ниже утверждённой границы после полного учёта затрат. Внутренний перевод бюджета не создаёт прибыль банка |
| Предлагаемый владелец | Руководитель РКО вместе с кредитным продуктом; риск, операции, финансы и аналитика |

Опора: BB-C0070, BB-C0071, BB-C0081. Ограничение: BB-C0074. Зарубежный банковский кейс не определяет доступную банку цену миграции.

## BB-O07. Документ → проверяемый черновик платежа

Проверяется вся задача от документа до корректного банковского исполнения. Быстро сформированный черновик может перенести работу на последующую проверку и не сократить общие затраты.

| Поле протокола | Проект проверки |
| --- | --- |
| Клиент и N | Внешние компании с частыми счетами поставщиков. Все назначенные компании и попытки обработки, включая ошибки и незавершённые платежи |
| Сравнение | Обычный ввод против подготовки черновика с подтверждением человеком. Одинаковые типы документов и платежей; заранее задать критерий корректности |
| Главный KPI | Полная стоимость корректно завершённой задачи: все затраты исходных попыток делятся на число корректных исполнений. Повторное использование — диагностическая метрика; при нуле исполнений KPI не определён |
| Данные и допуск | Раздельно хранить документ, извлечённые поля, исправления, согласование и банковское исполнение. Нужны журнал и контроль полномочий |
| Экономика | Включить распознавание, ручную проверку, исправления, поддержку и стоимость ошибок. Не приписывать черновику измеренный кредитный эффект |
| Остановка | Ошибки, несанкционированные действия или стоимость выше утверждённых границ даже при быстром черновике. Исполнение требует подтверждения уполномоченного человека |
| Предлагаемый владелец | Руководитель платёжного продукта/автоматизации; операции, безопасность, аналитика и финансы |

Опора: BB-C0390, BB-C0164, BB-C0337. Ограничение: BB-C0389. O07 может поддержать O02 или O05; отдельная разработка требует отдельного расчёта.
